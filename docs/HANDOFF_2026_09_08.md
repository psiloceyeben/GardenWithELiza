## 1. What the game is

A browser multiplayer "brainrot garden" game (Steal An Egg loop with original flora) whose *land* is derived from
Robinhood Chain state. Two layers with opposite physics:

- **Layer C, chain-derived land** — permanent, unstealable: plot count, biome palette, rarity floor, conviction tree,
  wither-mark stumps, decorative flora, hybrid seed unlocks. A pure function of a wallet address plus public chain
  state. Anyone can rebuild every garden from public data (documented as a feature).
- **Layer G, game state** — server-authoritative, stealable: Sap (soft currency), seeds, plants, defenses, cosmetics.

The governing sentence: *Your land is forever; your plants live and die by the raid.*

Legal spine (bible §0): the app is read-only on chain, holds nothing, never transacts, stock tokens/broker NFTs are
decoration only with zero gameplay effect, Sap never converts to anything, no referral wiring, no gambling copy,
original IP only. `tools/lint-copy.js` fails the build on banned copy in `content/`, `content/lore/`, NPC lines and
client source. `server/src/tests/derive.test.ts` locks I-3 (stock decor changes no gameplay value).

## 3. Every system, briefly, with the file that owns it

**World.** `shared/world.ts::buildVillage(seed)` — 120x80 tiles: hedge border, corner ponds, central plaza (48,32 size
24x16) with fountain, benches, lamps, board, conveyor stall, sprint track, signpost; 16 fenced lots (13x11 incl. fence,
gate facing the plaza, 20 plot slots in centre-first order; only `plotCount` of them are tilled); ring roads and spokes;
the **town street** at y=8..9, x=30..90 with five buildings at x=32,44,56,68,80 (hall, seedshop, tavern, shrine, tower)
and an NPC at (bx+1, 10); ~50 trees. Tiles: 21 kinds, packed 32 per biome row (`TILE_STRIDE`), 8 biome palette swaps
as separate sheets `tiles_b0..7`. Client tilemap uses one layer with gid = biome*32 + tile so each lot can wear its
wallet's biome. Collision: `moveActor` foot box vs `isWalkableTile` (blocked tiles + solid props + closed gates).
Pathing: `findPath` BFS over tiles; used by client tap-to-walk and the bot.

**Movement / anti-cheat.** Client predicts with the same `moveActor`; sends `{t:'input', x,y,d,f,m}` every 100 ms
while moving. Server accepts a position only if within `speed * dt * 1.35 + 6` px and re-runs collision
(`game.ts::onInput`). Snapshots 10/s per village; client snaps itself back if >48 px off.

**Economy.** `shared/economy.ts`. Conveyor 6 slots, refresh 5 min, tier odds with rarity floor lifting the minimum;
seed prices scale with plot count; growth 30 s (common) … 15 min (mythic); reveal rolls size 0.8–1.5 and a mutation
(golden ×4, holographic ×6, colossal ×3, feral ×5, backwards ×2, screaming ×8); Sap/s = base × size × mutation
× (0.5 if weedy). Weeds after 20 min untended. Watering shortens growth 10%. Offline accrual capped 8 h.

**The raid.** `game.ts::onUproot/onBreak/completeChannel/recover/score` + `tick`. Uproot channel 3 s (moving >6 px
cancels; owner within 22 px or gnome within 44 px cancels), carry at 0.7 speed (0.6 more with sprinkler, mud slows all
non-owners), score when inside own lot (not while visiting), tag returns plant + bounty (60 s of output, min 20),
offline shield + 10 min grace after login (`PONS_GRACE_MS` override for tests), 3 steals per victim per hour,
Mythics only when owner is in their own lot, closed gate = 3 break hits of 2 s each.

**Defenses / shop.** fence 300, repair 100, gnome 800, sprinkler 500, plot lock 150 (24 h), scarecrow 250 (public
view reports it as a gnome), mud 400, bell 150, sprint training 50×2^level. Public view via `publicDefenses()`.

**Bounties.** Victims post 50–2000 Sap on a `stolenBy` thief; stored on the thief's home `VillageRec.bounties`;
`SnapPlayer.b` marks WANTED; claimed by whoever tags them carrying.

**Villages as rooms / visits.** `rec.visiting` = village id when away. `Game.vid(rec)` = current village;
`map(rec)` current map; `homeMap(rec)` + `lot(rec)` home. Visitors spawn at the plaza, raid, and score by going home
through the signpost (`onVisit(null)`). Client reloads when a welcome arrives for a different village.
`PONS_LOT_CAP` (env) caps lots per village for tests.

**Phase one life.** `server/src/life.ts`: wild seeds (8 max, spawn every 90 s or `PONS_WILD_SPAWN_MS`, 10 min TTL,
rare+ announced), events every 20 min for 3 min on a shared clock (seed_rain / screaming_hour / golden_hour),
sprint lap track→fountain→track (+20, +50 record, 5 min cooldown, top-5 board persisted).

**Cosmetics / wardrobe / nicknames / trophies.** `rec.cosmetics` (fence wood|stone|hedge, lantern, nameplate, path,
gnomeHat), `rec.hat` + `rec.hats`, `rec.color` (shirt), `Plant.nick`, `rec.weekly` keyed by ISO week; `boardMsg()`.
Chars atlas frames are `farmer{shirt0-5}{hat0-3}_{down|up|side|carry}{0|1}` (192 frames).

**Town / missions / Oracle.** `shared/missions.ts` (5 NPCs, 10 daily missions, 3 active max);
`game.ts::onTalk/onMission/progress/onAsk`; progress hooks are in buy/plant/tend/reveal/forage/sprint/tag/steal/visit/ask.
`server/src/oracle.ts` POSTs `{text}` to `PONS_ORACLE_URL`; `status` `withheld`/`clarification` → persona shrug;
reply stripped of citation preambles, capped 280 chars, filtered against banned copy.

**Wallet / land (M2).** Guest identity is `{id, secret, name}` in localStorage. Linking: client `nonce` →
server message → wallet `personal_sign` → `link` → `verifySignature` → if the address already owns a player the
server sends `identity` (fresh secret) and the client saves + reloads as that player (wallet sign-in); otherwise
`applyGarden(deriveGarden(address, reader.snapshot(address)))`. Plots never shrink. Everyone starts with 10 plots;
ladder 12/14/16/18/20 (`shared/derive/constants.ts`).

**Share pages.** `share/render.ts` composes the lot from the atlases; served by `server/src/index.ts` with OG tags.
`PONS_PUBLIC_BASE` env sets the absolute image URL.

## 4. Protocol cheat sheet (`shared/protocol.ts`)

Client → server: `hello, input, buy, plant, tend, shop, uproot, break, cancel, chat, emote, rename, nonce, link, unlink,
forage, sprint, bounty, visit, home, villages, cosmetic, wardrobe, nick, talk, mission, ask, ping`.

Server → client: `welcome` (private state + village + public lots + players + names + feed + villages), `snap`,
`state` (partial private state), `lot` (public lot), `players`, `feed`, `reveal`, `toast`, `chat`, `emote`, `channel`,
`carry`, `error`, `nonce`, `linked`, `identity`, `wild`, `event`, `sprint`, `board` (sprint + bounties + trophies),
`villages`, `npc`, `say`, `pong`.

Rate limit: 60 messages/s per socket, chat 1 per 700 ms, ask 1 per 3 s.

## 6. The Oracle instance (how to update the NPC knowledge)

Builds live under `/opt/oracle-clm/fable-content/oracle-m-series-2026-08-15/ponsgarden_wiki_openstax_fable_build_a_v1`
and `…/ponsgarden_dbpedia_openstax_fable_bench_a_v1` (copies of the HOODBarons builds with the Pons corpus admitted).
The harness opens the SQLite immutably, so the sequence is:

```bash
ssh root@89.167.7.54 'P=/opt/oracle-clm/fable-content/oracle-m-series-2026-08-15; cd /opt/pons; systemctl stop oracle-harness-ponsgarden; for d in ponsgarden_wiki_openstax_fable_build_a_v1 ponsgarden_dbpedia_openstax_fable_bench_a_v1; do python3 tools/oracle/pons_admit.py --base $P/$d --out $P/$d --corpus content/lore/pons_lore_d3.jsonl --stamp pons_lore_YYYY_MM_DD; done; systemctl start oracle-harness-ponsgarden'
```

Corpus format: one JSON object per line `{title, aliases[], references[], sentences[]}`; sentences must be 4–60
words (rejected, never repaired). `pons_admit.py` creates `fb<N>` pages (N continues from the highest existing),
merges into an existing page when the normalized title exists (fable sentences lead), rebuilds the FTS claims,
and rewrites `manifest.json` metrics + sha so `validate_build` accepts it (metrics must equal the sqlite metadata
table exactly or the harness refuses to start with `wikipedia_index_metadata_changed`).

Probe: `curl -s -X POST http://127.0.0.1:8099/chat -H 'content-type: application/json' -d '{"text":"Who is Warden Pell?"}'`.
Known Oracle behaviour (not fixable from the corpus): questions resolve by head word, so "gnome sentry" hits the
GNOME desktop page and "Sap" hits SAP SE; hyphenated terms clarify. Prefer unique in-world titles for new pages.

## 7. Art pipeline

`tools/sprites/gen.py` (palette, canvas primitives, 20 plant bodies + gags, farmer/gnome, props, ui) and
`tools/sprites/gen_world.py` (tile strip + biomes, plaza props, buildings, NPCs, hats, decor, weeds). Every sprite is
a text-indexed pixel grid or a parametric drawer; output is PNG + Phaser JSON-hash atlases. Any sheet can be
overpainted in Aseprite as long as frame positions stay. Species visuals live in `VIS` in `gen.py` keyed by roster id;
adding a species = roster.json entry + VIS entry + regenerate. Mutations are runtime effects, never art.
Tile order in `gen_world.py::TILE_ORDER` must match `shared/world.ts::TILES`.

## 9. The requested 3D switch (HD-2D), design and steps

Goal from the owner: "3D, same skin and everything." Recommended approach: **HD-2D** — keep every atlas exactly as is,
render the world with Three.js, camera at a tilted three-quarter angle, sprites as billboards. Only the renderer changes.

Keep untouched: server, protocol, HUD (DOM), `net.ts`, `wallet.ts`, `audio.ts`, art pipeline, share renderer.
Replace: `client/src/scenes/WorldScene.ts` and `BootScene.ts` (Phaser) with a Three.js renderer. Suggested layout:

```
client/src/three/Renderer3D.ts   scene, camera, lights, resize, render loop (requestAnimationFrame)
client/src/three/Atlases.ts      loads the same PNG+JSON atlases into THREE.Texture with NearestFilter; frame → UV rects
client/src/three/Ground.ts       one BufferGeometry for the 120x80 tile grid (per-tile UV from tiles_b<biome>), slight
                                 height noise, MeshStandardMaterial; lots re-tile by updating UV attributes (gid = biome*32+tile)
client/src/three/Billboard.ts    quad that faces the camera (copy camera quaternion, keep upright), UV from atlas frame,
                                 alphaTest 0.5, animation = UV swap on a timer (idle 6 fps, walk 6 fps)
client/src/three/Props.ts        trees/props/NPCs/wilds as billboards; buildings + fences as thin boxes with the sprite on
                                 the front face and a darker side; lamps = PointLight children lit by the day cycle
client/src/game/WorldState.ts    the non-rendering half of today's WorldScene: message handling, lot views, path following,
                                 prediction, interaction targeting (extract it first; it is ~60% of the file)
```

Steps in order, each verifiable through the bot plus a screenshot:
1. Extract `WorldState.ts` from `WorldScene.ts` (message handling, lots map, wilds, remotes, path, prediction) with a
   small renderer interface (`spawnBillboard`, `moveBillboard`, `setFrame`, `retile`, `light`). Keep Phaser working
   through that interface first; run the bot; commit.
2. Add `three` as a client dependency (npm on Box C). Renderer3D with ground only; camera follows the player position
   from WorldState; zoom becomes camera distance (close / half / whole map = dolly out to frame the village).
3. Billboards for player, remotes, plants, NPCs, wilds, gnome; carry sprite above head; name tags as DOM overlays
   projected with `Vector3.project` (keeps text crisp) or sprite text.
4. Props: buildings as boxes, fences as low walls using the fence tiles as textures, gate open/closed.
5. Lighting: hemisphere + directional for day, night = lower intensity + lamps as point lights; Screaming = camera shake.
6. Effects: mutations (tint = material color, holographic = hue-cycle color, colossal = scale, backwards = flip UV,
   feral = position tween), weeds/lock/wet-mark as small billboards.
7. Query flag `?r=2d` keeps the Phaser scene selectable until 3D is proven, then remove Phaser.
Do not change `shared/world.ts` geometry: tile coordinates stay the world units (1 tile = 32 px = 1 unit ×32).
